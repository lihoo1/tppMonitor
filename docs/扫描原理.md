# 淘票票全天监控

当前源码里的城市发现（全天监控）怎么扫、打哪些接口、要不要 Cookie。对应代码：`all_day_monitor.py`、`taopiaopiao_api_pro.py` 的影院列表与排期方法、`main_app_pro.py` 的 `start_all_day_monitor`。

全天监控按「ShowID + 城市 + 日期」反复拉这个影片在该城市的影院，再查这些影院的排期，筛出见面会标签或接近票价白名单的场次。关掉「启用全天监控」就停止这轮城市扫描。

## 要不要 Cookie

扫描不要求登录 Cookie。没有导入账号也可以启动。客户端如果没带 `_m_h5_tk`，会先做一次 H5 握手，向服务端要签名令牌，再发影院列表和排期。

账号列表里有未过期 Cookie 时，启动监控会随机抽一条，作为这次扫描客户端的初始 Cookie。过期账号不抽。没有账号时这条 Cookie 为空，仍然走下面的握手。

签名用的是 H5 令牌 `_m_h5_tk` 下划线前面的那段。请求签名是 `MD5(token + "&" + 时间戳毫秒 + "&" + appKey + "&" + data)`，appKey 为 `12574478`。令牌空、过期或签名失败时，客户端用一次故意签错的轻量请求换新令牌：

- 接口：`mtop.film.MtopShowAPI.getShowList`，版本 `7.0`
- 地址：`https://wxapi.m.taopiaopiao.com/h5/mtop.film.mtopshowapi.getshowlist/7.0/`
- `sign` 固定 32 个 `0`，用来触发服务端在 `Set-Cookie` 里下发新的 `_m_h5_tk`

这条握手只续 `_m_h5_tk`。`cookie2`、`csg`、`munb` 这类登录字段不会被这次握手改掉。

## 扫描配置

入口在路演监控台「① 城市发现目标」。每条目标必须同时有 ShowID、城市、日期（`YYYY-MM-DD`）。顶部 ShowID 在点「添加城市日期」时绑到那一条上；多条城市可以绑不同的 ShowID，绑好之后不会交叉扫描。发现间隔默认 10 秒，范围 1 到 1800 秒。开关「启用全天监控」记在设置 `monitor/enabled`，默认开。

和扫描过滤有关的勾选：

- **只扫见面会标签**（默认开）：优先按标签筛。票价白名单不为空时，没有标签的影院也会查排期，只保留接近白名单的场次。
- **启动时处理已有场次**（默认开）：第一次扫到的场次也记为命中。关掉则第一次只记基线，之后新出现的场次才记为新命中。

票价白名单在「③ 过滤规则与轮询节拍」的「票价」框，默认 `69,99,199,299,399,405,499,398.9`。界面上小于 10000 的数按元换算成分（乘 100），否则直接当成分。内部默认分档是 `6900, 9900, 19900, 29900, 39900, 40500, 49900, 39890`。

## 监控接口

公共前缀：`https://wxapi.m.taopiaopiao.com/h5/`。请求是 mtop H5：`H5Request=true`，`type=jsonp`，`data` 为紧凑 JSON。公共字段包括 `platform=42`、`comboChannel=108`、`dmChannel=damai@tppnewh5_h5`。

全天监控只用下面两个业务接口。城市全量影院接口 `getCinemaListInPage` 的 `pageCode=APP_CINEMA` 存在于客户端里，这条监控不调用它。

### 1. 按影片拉城市影院

- 方法：`MTopClientPro.get_show_cinemas`
- 接口：`mtop.film.MtopCinemaAPI.getCinemaListInPage`，版本 `8.0`
- 路径：`/h5/mtop.film.mtopcinemaapi.getcinemalistinpage/8.0/`

主要参数：

| 字段 | 当前取值 |
| --- | --- |
| showId | 这条城市绑定的 ShowID |
| cityCode | 目标城市编码 |
| showDate | 日期换成东八区当天 0 点的 Unix 秒时间戳 |
| pageIndex | 从 1 开始 |
| pageSize | 100 |
| pageCode | `APP_SHOW_CINEMA` |
| needShowItem | `false` |
| sortType | 3 |
| version | `20220210` |
| longitude / latitude | `0` / `0` |

读响应 `data.returnValue.cinemas[]`。每家影院留下 `cinemaId`、`cinemaName`、`showTimeStr`（没有则用 `showTime`），标签来自 `supportList[].tagName`（没有则用 `tag`），拼成一段文字。同一页里重复的影院 ID 丢掉。某一页条数少于 100，或这一页没有新影院，就停止翻页。最多 50 页，超过则这轮该城市报错并进入退避。

### 2. 查单家影院排期

- 方法：`MTopClientPro.get_cinema_schedules`
- 接口：`mtop.film.MtopScheduleAPI.getNewCinemaSchedules`，版本 `2.0`
- 路径：`/h5/mtop.film.mtopscheduleapi.getnewcinemaschedules/2.0/`
- 超时：3 秒

主要参数：`cinemaId`、`h5AccessFlag=1`、`isMovieDate=0`，以及上面的公共渠道字段。经纬度固定为杭州附近的 `30.27415, 120.15515`，只作为请求体字段，不参与选城。

读响应：

- `data.returnValue.showVos[]`：影片名 `showName`、影片标签 `specialTag`
- `data.returnValue.showScheduleMap[showId][]`：按天的排期。日期字段按 `date`、`showDate`、`dateStr`、`dateDesc`、`dateTip` 依次取第一个非空值
- 每天的 `scheduleVos[]`：`scheduleId`、`scheduleTag`、开场时间 `openTime`（没有则用 `showTime`）、票价 `tradePrice`（没有则用 `memberTradePrice`），单位是分

日期匹配接受 `2026-10-01`、`2026/10/01`、`20261001`、`10月1日`，以及秒或毫秒时间戳。只保留目标日期、且 ShowID 在本轮配置里的场次。

## 一轮扫描怎么走

`AllDayMonitor.run` 在独立的 `monitor` 事件循环里转。一个城市失败不会停掉其它城市。

1. 最多 4 个城市同时扫（`CITY_CONCURRENCY = 4`）。每个城市的键是 `(ShowID, 城市编码, 日期)`。还在退避窗口里的城市本轮跳过。
2. 翻页拉影院列表。
3. 决定要查排期的影院：
   - 「只扫见面会标签」开着，且白名单非空：列表里的影院全部查排期。
   - 「只扫见面会标签」开着，白名单为空：只查带标签的影院。
   - 勾选关掉：列表里的影院全部查排期，不再按标签或票价过滤。
4. 同一城市内最多 48 家影院同时查排期（`SCHEDULE_CONCURRENCY = 48`），请求之间不再额外等待（`REQUEST_SPACING = 0`）。每查完 25 家，或查完最后一家，界面更新「已核对 x/y 家」。
5. 从排期里抽出命中。抽场次时不再按标签重滤一遍。
6. 这一波结束后休眠。至少有一个城市扫完时，休眠「发现间隔」；一个都没扫成时，休眠 `min(发现间隔, 30)` 秒。

见面会标签是这四个子串，出现在影院 `supportList`、影片 `specialTag` 或场次 `scheduleTag` 的拼接结果里就算：

`明星见面会`、`映后见面会`、`主创见面会`、`路演`

票价过滤只作用于「没有这些标签」的影院：实际票价与白名单任一档相差不超过 100 分（1 元）即保留，并在标签末尾加上「白名单票价」。例如白名单有 19900 时，接口返回 19990 会命中，18900 不会。白名单为空表示这一步不按票价挡。有标签的影院保留该 ShowID、该日期下抽出的场次，不要求票价落在白名单里。

带标签的影院如果排期里抽不出场次，但 `showVos` 或 `showScheduleMap` 里已经出现这个 ShowID，会补一条占位命中：`scheduleId` 为 `list-{cinemaId}`，票价 0，开场时间用列表上的 `showTime`。

同一次运行里，`(影院 ID, scheduleId)` 只记一次。第一次扫某个城市时，若「启动时处理已有场次」关掉，这些场次记为「已在映（启动基线）」，之后新出现的才记为新命中。

一条命中里带着：城市、影院 ID 与名称、ShowID、影片名、scheduleId、日期、开场时间、标签、票价（分）。

## 失败与重开客户端

某个城市本轮抛错（接口 `success` 不为真、缺 `cinemas`、缺 `showScheduleMap`、分页超过 50 页等）时，该城市单独退避：等待 `发现间隔 × 2^失败次数`，失败次数按 4 封顶，最长 300 秒。界面状态变为「请求异常，自动重试」。

同一城市连续失败达到 3 次后，这一波全部城市扫完，关掉当前 HTTP 客户端，用启动时那条 Cookie（可能为空）再建一个。重建发生在这一波结束之后，不在请求飞着的时候换客户端。令牌类错误（响应 `ret` 含 `TOKEN_EMPTY`）若客户端上已经有 token，会先原样再请求一次。

手动停止或关掉「启用全天监控」只停这条扫描循环。
